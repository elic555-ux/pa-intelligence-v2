# Explicit multi-view trial

`property_bundle_quality_trial.py` sends seven pinned original JPEG files in one
ordinary `report_gemini.collect` request: three kitchen views, two exterior wood
views and two garage views. Only the intake is replaced with saved, checksum-bound
source bytes. Provider generation, request validation, cache and the 20-attempt
daily reservation ledger remain real. There is no automatic retry or paid fallback.

The fixture manifest SHA is pinned in code. It binds the source listing, image URLs,
the listing identity and every file SHA. The live inventory must contain exactly
one matching property. Owner labels and the expected scope are not sent to the model.

The workflow writes reservations and results through a separate `main` data
checkout. It refuses a branch/code checkout for those writes. It does not update
`expanded_reports`, `expanded_receipts` or the live photo report. Changing the
explicit diagnostic trigger is required for a new trial.

The initial evaluation checks seven real images, coverage and no invented budget.
A valid response remains `pending_independent_review`: contract success is not
evidence of correct diagnosis, correct grouping or general accuracy. Provider
failure is `not_evaluated`, not a failed visual judgment. Review the actual findings
and scope against the stored images and owner's separate observations.
